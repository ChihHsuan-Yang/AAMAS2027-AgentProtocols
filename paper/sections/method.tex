\section{Intervention}
\label{sec:method}

We vary organization in both directions from one baseline: we remove it, and
we enforce it. All conditions share three agents, one interaction order
(Planner~$\rightarrow$~Executor~$\rightarrow$~Reviewer), the message-passing
graph, context visibility (except under enforcement, below) and the total
call budget. They also use the same verifier and prompt, retry budget,
decoding parameters (temperature $0$, that is, greedy decoding, and
identical \texttt{max\_tokens}), stopping rule (a PASS ends the trajectory)
and grading. Every trajectory in the frozen snapshot carries the identical
budget record, so the design tests organization, not scale. Besides the
roles, three things differ. After a FAIL, the evaluator returns a repair
hint, written with the gold answer (the reference solution) in view and
instructed not to reveal it. The role-structured and enforced templates show
the hint to all three agents in the next cycle, each through its role's
advice slot, the template field reserved for the evaluator's feedback
(Figure~\ref{fig:pipeline}). The role-free template has no such slot, so we
report the role-free condition both without and with the feedback. The
role-free footer (the closing instruction of the prompt) also asks every
agent for an answer, and the role-structured Reviewer carries two clauses
the role-free prompt lacks.

\paragraph{Role-structured \PER{} (baseline).} Role prompts are as
ordinarily written. The Reviewer is told to approve only a complete answer
of the right shape. In a cycle that receives a FAIL, it is told to route the
work back to the Planner or Executor rather than approve.

\paragraph{Role-free, feedback withheld.} All three agents receive one
byte-identical prompt, ``You are one of three agents collaboratively solving
this problem. Continue the work.'', followed by the problem, the shared
history and the agent's slot number (its position, first to third). A footer
asks for the agent's current best answer in \texttt{\textbackslash
boxed\{\}} and a closing \texttt{[Agree]} (ready to submit) or
\texttt{[Continue]}, the conventions the role-structured Executor and
Reviewer use. Every clause saying who does what is removed, above all the
Planner's \textsc{must not}s on computing and answering. In every prose
condition, the third agent's \texttt{[Agree]} is approval (a message with
neither tag counts as \texttt{[Continue]}), and the latest boxed answer is
submitted. Nothing in this template carries the evaluator's verdict or hint.

\paragraph{Role-free with feedback.} This condition uses the same role-free
prompt, byte for byte, plus the evaluator's verdict and repair hint, the
string the role-structured team receives. All three agents see it as an
\texttt{[Evaluator]} entry after the shared history in the cycle after a
FAIL, so it stays visible for one cycle, as the advice slot does. It differs
from the feedback-withheld condition only in the feedback.

\paragraph{Structurally enforced.} The interface, not the wording, enforces
specialization. The Planner emits JSON (a typed output format) against a
schema with \emph{no answer field}, so a final answer is unrepresentable.
The Executor receives the parsed plan object and the problem, never the
Planner's raw text, and emits a derivation and an answer. The Reviewer emits
a verdict, a target span and a critique. Its \texttt{accept} promotes the
Executor's answer verbatim \emph{by reference}, because it has no field in
which to \emph{author} one. Each function stays with one agent under the
same budget, but the Executor sees less context, and a rejected output can
exhaust the regeneration budget (the number of times a malformed output may
be regenerated). A \emph{context-restored control} repeats this condition
with the shared history restored.

\paragraph{Single-agent reference.} A budget-matched single-agent protocol
on the same problems guards against multi-agent gains that merely mimic a
single capable agent~\cite{zhang2026rethinking}. It comes from a previously
released corpus rather than this campaign (\S\ref{sec:experiments}). The
comparison cuts both ways, and the arms come from separate runs
(supplement).

\subsection{Instrumentation and pre-registered analyses}
\label{subsec:prereg}

An intervention that never engages cannot explain an outcome, so we measure
engagement. We log every rejected-and-regenerated output with its reason,
count only role-boundary violations in the enforcement rate, and count
answer-bearing calls per condition. One logging gap slipped through
(\S\ref{subsec:logging}).

All five endpoints (the pre-specified analyses) were fixed in writing and
committed before any intervention data existed. The full table, with the
outcome for each, is in the supplement. Units are (problem, actor) pairs,
and all conditions run the same problems, so every test is paired, with
bootstrap intervals that resample whole problems~\cite{efron1979bootstrap}.
The pre-registered primary endpoint, P4, asks whether enforcement's effect
on accuracy differs by actor. It is null: no pairwise
difference-in-differences (enforcement's effect in one actor minus its
effect in another) survives Holm's correction for multiple
comparisons~\cite{holm1979simple} (smallest adjusted $p=0.17$). Before
correction, the interval for the Llama-3.3 model against gemma-4, $+0.040$
$[+0.001,+0.080]$, only just excludes zero, and a separate resample gives
$p=0.055$. Only the gpt-oss against gemma-4 contrast had adequate
statistical power for an interaction of plausible size.

The \Pone{} manipulation objective also failed. It required enforcement to
drive Planner computation-abstention to ${\approx}1.0$, but the schema
forbids an \emph{answer}, not a computation. It was re-designated to answer
authorship. The role-structured versus role-free contrast this paper is
organized around was pre-registered as a secondary, exploratory replication
of a published null, and splitting it into phases is post hoc. The role-free
condition with feedback was added after the freeze (when the dataset and
analysis plan were fixed). Its design and primary analysis were committed in
writing before any of its data existed, but its results are exploratory.
Exclusions were fixed in advance, including the rule that decides
\S\ref{subsec:enforce}: \emph{unparseable trajectories count as incorrect
rather than dropped}.

## 1. OmniMath2: 4,181 available -> 1,600 run

- full matched pool: **4181**
- scientific run: **1600** (38.3%)
- seed: **20270101**, drawn by `runner.load_problems(n=1600, seed=20270101)`
- manifest: `experiments/manifest_omnimath2_n1600.json`

**Procedure** (verbatim from `runner.py:load_problems`): filter to the
benchmark, require `problem_text` and `answer` non-null, sort by
`problem_uid` with a stable mergesort, shuffle the index with
`random.Random(seed)`, take the first n, re-sort. Deterministic and
independent of row order in the parquet.

**It is a uniform random sample of the whole pool — not a tier-specific,
difficulty-stratified, or otherwise purposive subset.**

## 4. SciBench denominators: 692 upstream -> 580 released -> 574 matched

- upstream SciBench (published): **692**
- present in the released problems table: **580**
- carrying the `text_only` slice, i.e. the matched scientific run: **574**
- **run in this campaign: 574 problems x 2 actors x 2 arms = 2,296 trajectories**

### Where the 692 - 580 = 112 go

**NOT RECOVERABLE FROM THIS RELEASE, and I will not guess.** The released
problems table contains only rows that survived the upstream build, so the
112 excluded items are absent from it entirely and carry no reason code
here. A first draft of this audit asserted they were figure/table/tool
items plus collisions; that was an inference presented as a measurement
and has been removed.

What the release *does* record, for the 580 rows that are present:

| collision_status | n |
|---|---:|
| unique | 574 |
| conflicting_source_id_disambiguated | 6 |

Note the 6 `conflicting_source_id_disambiguated` rows are **not** the same
6 rows that lack the text-only slice — they are disjoint sets, so the two
subtractions below are independent, not the same six items counted twice.

To establish the 112 one would have to diff the upstream SciBench release
against this table. That is tracked as a P2 item; it does not affect any
denominator this paper reports, because the paper's denominator is the 574
it actually ran.
